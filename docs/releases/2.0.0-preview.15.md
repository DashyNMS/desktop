A preview of DashyNMS v2.0.0 for **Windows, macOS and Linux**.

These notes cover changes since [preview 14](https://github.com/DashyNMS/desktop/releases/tag/v2.0.0-preview.14).

## Changed

- **Updated Intelligence network tools.** The tools Intelligence uses to look things up are updated to the latest reviewed release. They say more plainly when a source couldn't be read, was only sampled or was cut short, and Intelligence reports that as unknown rather than as healthy or empty. Their licence and the licences of everything bundled with them now ship alongside them.
- **Starter questions.** "Which devices have been up the longest?" is replaced by "Which devices carry the most traffic?". Uptime can only be checked one device at a time, so the old question used up a question's lookups without a complete answer.

## Fixed

- **Intelligence uses your health thresholds.** Intelligence now judges sensors with the bands and the **Always use these app thresholds** choice from **Settings, Health thresholds**, so its answers match the Health tab. A saved change applies from the next question. If a band's values are out of order, Intelligence tells you which section to correct.
- **Acknowledged and recovered alerts in Spotlight.** Asking Intelligence about an alert that has been acknowledged or has recovered no longer says it's unavailable. Only that exact alert is accepted, never a similar one or its device.
- **Answers after signing out or switching.** If you sign out, switch LibreNMS server or account, or save a setting Intelligence uses while it is looking something up, those lookups are discarded. They no longer finish into the answer under the new connection or settings. Signing out also stops the network tools straight away.
- **Device names can't steer Intelligence.** Spotlight now tells the model only the kind and ID of each object you've chosen. Names stay in the app, so a device, group or location name written to look like an instruction is read only as data.
- **Exported chats with stopped code.** In a Markdown export, an answer stopped part-way through a code block no longer turns the rest of the chat into code. Code blocks written with `~~~` are now recognised in chats, PDFs and exports.
- **Sensor definitions on macOS.** The sensor definitions settings stay in the app data folder on macOS.

## Trying this preview

Report issues through [GitHub issues](https://github.com/DashyNMS/desktop/issues), including your operating system and, on Linux, your desktop environment. If an Intelligence answer about sensors disagrees with the Health tab, please include the sensor type and your threshold settings, but not device names or addresses.

Mac downloads use Developer ID signing and Apple notarisation. Windows distribution signing remains tracked in [#109](https://github.com/DashyNMS/desktop/issues/109).
