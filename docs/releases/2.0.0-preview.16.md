A preview of DashyNMS v2.0.0 for **Windows, macOS and Linux**.

These notes cover changes since [preview 15](https://github.com/DashyNMS/desktop/releases/tag/v2.0.0-preview.15).

## New

- **Network Search.** Find anything on your network from one box: an IP address, a network such as `192.0.2.0/24`, a MAC address in any format, a device name, or a pasted list of them. Open it from the search icon under Intelligence in the sidebar, or press **Ctrl+Shift+F** (**Cmd+Shift+F** on macOS) on any page. **Ctrl+F** still searches the page you're on.
  - **Connected to** comes first, laid out like the neighbour cards in device details.
    - For an address LibreNMS doesn't monitor, it shows the switch and port the address plugs into: the switch's state, whether the address is alone on the port, its VLAN, how recently it was seen, and the port's status and traffic.
    - For a monitored switch or server, it shows every neighbour the device is linked to.
    - When LibreNMS can't name the link, it shows where the MAC address was learned instead.
  - Below that are the address's IP and MAC addresses (with the MAC's maker), every switch port that learned it with uplinks marked, its subnet and gateway, and the routers whose ARP tables know it. Every switch, port and interface opens in device details, and any value can be copied.
  - A search that matches a monitored device opens with a summary of that device.
  - When one address answers from several MACs, or one MAC appears on several access ports at once, a **Conflicts** card points it out.
  - A network or list search shows a sortable list. Narrow it with **Filter**, by where each result was found, which router knows it, and whether LibreNMS monitors it.
  - Your recent searches are kept so you can switch back to one. Results can be copied or saved as CSV.
  - The status bar shows which sources were checked. If a source couldn't be read, say because your account isn't allowed to see switch MAC tables, the page says so rather than reporting the address as not found.
- **MAC address format.** Choose how Network Search shows MAC addresses (`aa:bb:cc:dd:ee:ff`, `aa-bb-cc-dd-ee-ff`, `aabb.ccdd.eeff` or `aabbccddeeff`) in **Settings, Devices, MAC addresses**. Searches accept any format.

## Fixed

- **VLANs in the MAC table on LibreNMS 26.11.** LibreNMS 26.11 changed how it reports the VLAN a MAC address was learned on, and the **MAC table** in device details showed no VLANs. They show again, on 26.11 and on older servers. A VLAN that can't be worked out now shows as "-" instead of a number that wasn't the VLAN.
- **Alert rules that use columns LibreNMS 26.11 removed.** LibreNMS 26.11 removed the device SNMP settings, the MAC table's old VLAN column, the Proxmox table and a few others. Rules that test them are flagged in the rules list and editor with advice on what to use instead, and new conditions offer only the fields your server has. The MAC table's VLAN is now the VLAN number itself, so a rule that compared the old internal value needs its value re-entering. DashyNMS never rewrites a rule for you.
- **Intelligence and LibreNMS 26.11.** The network tools Intelligence uses show VLANs and report rule columns correctly on LibreNMS 26.11.

## Trying this preview

Report issues through [GitHub issues](https://github.com/DashyNMS/desktop/issues), including your operating system and, on Linux, your desktop environment. If Network Search puts something on the wrong port, please include the status bar's list of what was checked and whether the port it chose is a link between switches, but not device names, addresses or MAC addresses.

Mac downloads use Developer ID signing and Apple notarisation. Windows distribution signing remains tracked in [#109](https://github.com/DashyNMS/desktop/issues/109).
