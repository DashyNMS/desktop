A preview of DashyNMS v2.0.0 for **Windows, macOS and Linux**.

These notes cover changes since [preview 8](https://github.com/DashyNMS/desktop/releases/tag/v2.0.0-preview.8).

## New

- **Optional error and usage sharing.** The first normal launch asks what you want to share. Error reports and basic usage statistics have separate, initially unchecked choices. Choose either, both, or **Don't share**. Closing the prompt leaves sharing off and asks again next launch. An explicit choice is remembered and can be changed in **Settings, About**.
- **Sanitised managed error reports.** Consented reports contain version, operating system, architecture, exception types and application method names. They exclude exception messages, file paths, log files, credentials, monitored network data and Intelligence content. Fatal errors wait locally for a later launch. Native crashes and memory dumps are not sent.
- **Basic launch statistics.** Usage sharing records an app-launch event with its version and platform. There is no user or installation identifier, so these are launch counts rather than unique-user counts. Demo and screenshot modes never send reports.

Sentry receives connection information when reports are sent. Disabling sharing cancels pending delivery and removes the affected reports from the local queue. Reports already received by Sentry follow the project's retention policy. Read the [privacy notes](https://github.com/DashyNMS/desktop/blob/master/PRIVACY.md) before choosing.

## Fixed

- **App shutdown.** Quitting now follows a single shutdown path. Closing the main window no longer requests shutdown a second time while shutdown is already in progress. This addresses the recursive shutdown path investigated after the macOS exit-crash report.

## Trying this preview

Report issues through [GitHub issues](https://github.com/DashyNMS/desktop/issues), including your operating system and, on Linux, your desktop environment.

Mac downloads retain Developer ID signing and Apple notarisation. To check an installed copy, run:

```bash
codesign --verify --deep --strict /Applications/DashyNMS.app
spctl --assess --type execute --verbose=4 /Applications/DashyNMS.app
```

The signature check exits successfully without output. Gatekeeper should report `accepted` and `source=Notarized Developer ID`.

Windows distribution signing remains tracked in [#109](https://github.com/DashyNMS/desktop/issues/109).
